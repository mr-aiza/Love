# راه‌اندازی ورود حساب‌های خانه‌ی ما

این نسخه ورود حساب واقعی روی سرور را اضافه می‌کند. نام کاربری‌ها `424` (علیرضا) و `626` (صبا) هستند. هنگام راه‌اندازی اولیه، برای هر دو حساب رمز دلخواه وارد کنید؛ اگر می‌خواهید همان رمز موردنظرتان باشد، دقیقاً `دوست دارم` را وارد کنید. رمز به شکل هش PBKDF2 در KV ذخیره می‌شود، نه متن ساده.

## نصب روی Cloudflare Worker

1. در Cloudflare، Worker فعلی `ourhome` را باز کنید و کد فایل `worker.js` این بسته را جایگزین کنید.
2. در **Settings → Variables and Secrets** دو متغیر بسازید:
   - `ORIGIN` = `https://mr-aiza.github.io` (فقط origin؛ مسیر `/Love` را اضافه نکنید)
   - `SETUP_KEY` = یک عبارت تصادفی و طولانی که فقط خودتان بدانید. این کلید، رمز ورود سایت نیست؛ فقط برای ساخت یک‌باره حساب‌هاست.
3. در **Settings → Bindings** همان KV Namespace با نام binding برابر `DB` را حفظ کنید.
4. Deploy کنید.

## انتشار سایت

همه فایل‌های این بسته را در پوشه‌ی ریشه‌ی همان مخزن GitHub Pages قرار دهید و commit کنید. `config.js` باید به `https://ourhome.bytelab.workers.dev` اشاره کند. بعد از انتشار، سایت را با آدرس `https://mr-aiza.github.io/Love/` باز کنید.

## ساخت حساب‌ها (فقط یک بار)

1. صفحه ورود را باز کنید و «راه‌اندازی اولیه حساب‌ها» را بزنید.
2. مقدار `SETUP_KEY` که در Cloudflare ذخیره کرده‌اید را وارد کنید.
3. رمز مشترک را وارد و تکرار کنید. برای خواسته فعلی، هر دو فیلد رمز باید دقیقاً `دوست دارم` باشند.
4. حساب‌ها ساخته می‌شوند و مرورگر با حساب `424` وارد می‌شود. سپس صبا می‌تواند با نام کاربری `626` و همان رمز وارد شود.
5. پس از ساخت حساب‌ها، کلید راه‌اندازی دیگر قابل استفاده نیست؛ حساب‌ها دوباره ساخته نمی‌شوند.

## امنیت و ذخیره‌سازی

- ورود توسط Worker بررسی می‌شود؛ بدون حساب، API اطلاعات را نمی‌دهد.
- رمز با PBKDF2 و salt تصادفی هش می‌شود. نشست ورود توکن تصادفی دارد و پس از ۳۰ روز منقضی می‌شود.
- دکمه خروج، نشست جاری را از KV حذف می‌کند.
- داده‌های مشترک در KV ذخیره و بین دو دستگاه همگام می‌شوند. داده‌های قدیمی‌ای که فقط در مرورگر مانده‌اند، خودکار از فضای قبلی وارد حساب تازه نمی‌شوند؛ قبل از راه‌اندازی از صفحه تنظیمات پشتیبان بگیرید.
- نام کاربری‌ها کوتاه‌اند و رمز «دوست دارم» قابل حدس است؛ اگر حریم خصوصی حساس است، بهتر است بعداً رمز قوی‌تر انتخاب شود.
- این پیاده‌سازی ورود دونفره‌ی اختصاصی است، نه سرویس عمومی ثبت‌نام. ساخت حساب از مسیر عمومی بسته است.

## رفع خطا

- `متغیر SETUP_KEY` یا `ORIGIN` تنظیم نشده: متغیرها را در Worker بررسی و Deploy کنید.
- `دامنه مجاز نیست`: مقدار `ORIGIN` باید دقیقاً `https://mr-aiza.github.io` باشد.
- `حساب‌ها قبلاً راه‌اندازی شده‌اند`: ساخت اولیه موفق شده است؛ از صفحه ورود استفاده کنید.
- بعد از به‌روزرسانی، اگر فایل‌های قدیمی دیده می‌شوند، صفحه را با refresh سخت باز کنید یا cache مرورگر را پاک کنید؛ نسخه Service Worker افزایش یافته است.

# خانه‌ی ما — نسخه توسعه‌یافته

این نسخه، ساختار قبلی را حفظ می‌کند و چهار صفحه جدید اضافه می‌کند:
- `chat.html`: چت دونفره متنی
- `games.html`: بازی دوز، حقیقت یا جرئت و سؤال‌های شناختی
- `map.html`: نمایش نقشه، دریافت GPS با مجوز کاربر، اشتراک‌گذاری زمان‌دار و مکان‌های خاطره
- `settings.html`: تنظیم تاریخ رابطه، نام‌ها، پوسته و پشتیبان‌گیری

صفحات قبلی و `pledge.html` حفظ شده‌اند.

## اجرای محلی
فایل‌ها را روی یک وب‌سرور محلی یا هاست استاتیک HTTPS قرار دهید. برای GPS، `file://` قابل اتکا نیست؛ از HTTPS یا localhost استفاده کنید.

## ذخیره‌سازی و همگام‌سازی
- بدون پیکربندی API، داده‌ها در مرورگر همان دستگاه ذخیره می‌شوند.
- چت و بازی روی دو دستگاه تنها زمانی همگام می‌شوند که فضای مشترک و Worker فعال باشد.
- در `config.js` مقدار `window.OURHOME_API` را به URL واقعی Cloudflare Worker تنظیم کنید.
- در Cloudflare یک KV Namespace با Binding دقیق `DB` بسازید.
- در Worker متغیر محیطی `ORIGIN` را روی مبدأ دقیق سایت تنظیم کنید، مثلاً `https://example.com` (بدون اسلش انتهایی). نسخه جدید Worker در صورت نبودن `ORIGIN` درخواست‌ها را رد می‌کند.
- فایل `worker.js` را به‌عنوان Cloudflare Worker مستقر کنید و مطمئن شوید `DB` به KV متصل است.
- سپس از صفحه خانه گزینه «ساخت فضای مشترک دو نفره» را انتخاب و لینک دعوت را فقط با شریک رابطه به اشتراک بگذارید.

## نکات محدودیت و امنیت
- دعوت فعلی با لینک دارای توکن انجام می‌شود؛ هرکس لینک را به دست آورد می‌تواند به فضای مشترک دسترسی داشته باشد. لینک را در فضای عمومی منتشر نکنید.
- این نسخه سیستم کامل ثبت‌نام/ورود و مدیریت چند دستگاه نیست؛ لینک دعوت نقش دسترسی دارد.
- همگام‌سازی از KV انجام می‌شود و برای چت/بازی زنده و پرترافیک، دیتابیس و زیرساخت realtime اختصاصی مناسب‌تر است. وضعیت دوز در این نسخه روی یک کلید مشترک نگهداری می‌شود و جایگزین سامانه بازی رقابتی با تراکنش اتمیک نیست.
- موقعیت زنده تنها با اقدام کاربر و مجوز مرورگر فعال می‌شود. توقف دستی، زمان انقضا و حذف موقعیت از فضای مشترک تعبیه شده‌اند. موقعیت دریافت‌شده فقط برای ذخیره محلی در `sessionStorage` نگهداری می‌شود و با بستن زبانه پاک می‌شود.
- GPS به HTTPS و پشتیبانی مرورگر نیاز دارد. پشتیبانی از به‌روزرسانی در پس‌زمینه محدود به سیستم‌عامل و مرورگر است.
- نقشه از OpenStreetMap استفاده می‌کند و برای نمایش آن اتصال اینترنت لازم است.
- قابلیت‌های تماس تصویری، هوش مصنوعی، آپلود ابری رسانه، رمزنگاری سرتاسری، اعلان Push کامل و حساب کاربری مستقل هنوز پیاده‌سازی نشده‌اند؛ برای آن‌ها به سرویس‌های بک‌اند و تنظیمات اضافه نیاز است.
- پشتیبان JSON اکنون داده‌های برنامه را صادر می‌کند، اما به دلایل حریم خصوصی مختصات GPS زنده را وارد پشتیبان نمی‌کند. فایل پشتیبان را محرمانه نگه دارید.
- قبل از انتشار، روی دامنه واقعی، دو گوشی و مرورگرهای هدف تست انجام دهید و از داده‌های فعلی نسخه پشتیبان تهیه کنید.

## فایل‌های مهم
- `app.js`: منطق برنامه و صفحات
- `style.css`: طراحی مشترک
- `worker.js`: API فضای مشترک
- `config.js`: نشانی Worker
- `sw.js`: سرویس‌ورکر و cache نسخه چهارم


## تغییرات نسخه همگام‌سازی زنده
- تاریخ شروع پیش‌فرض روی ۷ مهر ۱۴۰۵ تنظیم شده است (۲۰۲۶-۰۹-۲۹).
- روزشمار همه روزهای تقویمی را حساب می‌کند و روز شروع، روز اول محسوب می‌شود.
- تاریخ شروع رابطه در فضای مشترک همگام می‌شود؛ تغییر آن از تنظیمات برای هر دو نفر اعمال می‌شود.
- پس از ایجاد فضای مشترک، لینک دعوت را از صفحه خانه برای پارتنر ارسال کنید. خاطرات، نامه‌ها، آرزوها و رویدادها با فاصله تقریبی ۳ ثانیه بررسی و همگام می‌شوند. این همگام‌سازی polling است، نه اتصال WebSocket آنی.


## دسترسی فقط-مشاهده در برابر ویرایش
- پس از استقرار این نسخه از `worker.js`، فضای جدید دو توکن ویرایش (برای دو عضو) و یک توکن مشاهده دارد.
- لینک «لینک ویرایش پارتنر» را فقط برای پارتنر بفرستید؛ این لینک اجازه تغییر داده‌ها را می‌دهد.
- لینک «ساخت لینک فقط-مشاهده» برای دیگران است؛ دارنده لینک می‌تواند خاطرات و اطلاعات همگام‌شده را ببیند، اما رابط کاربری و API هر دو ویرایش را مسدود می‌کنند.
- اگر فضای مشترک قبلاً ساخته شده، بعد از Deploy کردن Worker جدید، یکی از دو عضو وارد سایت شود و دکمه «ساخت لینک فقط-مشاهده» را بزند تا توکن مشاهده برای همان فضای قبلی ساخته شود.
- این مدل، لینک‌محور است و حساب کاربری/هویت مستقل ندارد: هرکس لینک ویرایش پارتنر را دریافت کند می‌تواند ویرایش کند. لینک ویرایش را خصوصی نگه دارید. لینک فقط-مشاهده نیز برای هرکس که آن را داشته باشد قابل استفاده است.
